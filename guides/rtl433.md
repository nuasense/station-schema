# rtl_433 → NuaSense

Most cheap weather stations sold under names like Bresser, Froggit, Fine Offset, Oregon Scientific, LaCrosse, Ecowitt (the 433/868 MHz sensor arrays) can be received without their console: a 10-euro RTL-SDR stick on a Raspberry Pi and [rtl_433](https://github.com/merbanan/rtl_433) decode them to JSON. From there one hop gets the readings into NuaSense, with the agronomy computed on them.

The same works for an [OpenMQTTGateway](https://docs.openmqttgateway.com/) on an ESP32, which emits rtl_433's JSON over MQTT.

## 1. rtl_433 to MQTT

```sh
rtl_433 -f 868.3M -C si -F "mqtt://localhost:1883,retain=0,events=rtl_433/events"
```

`-C si` makes rtl_433 report °C, m/s and mm. For 433 MHz sensors use `-f 433.92M`. One JSON event per received packet, for example from a Fine Offset WH65B:

```json
{"time":"2026-11-02 15:02:11","model":"Fineoffset-WH65B","id":227,"battery_ok":1,"temperature_C":17.4,"humidity":90,"wind_dir_deg":110,"wind_avg_m_s":2.0,"wind_max_m_s":4.5,"rain_mm":254.0,"uv":1,"uvi":1,"light_lux":4134,"mic":"CRC"}
```

`rain_mm` is a running total since the sensor's last reset. NuaSense wants exactly that (`rain_total_mm`) and turns it into per-reading increments itself.

## 2. One hop to NuaSense

**Node-RED (simplest):** install `node-red-contrib-nuasense`, import the example flow [`rtl433-to-nuasense.json`](https://github.com/nuasense/node-red-contrib-nuasense/blob/main/examples/rtl433-to-nuasense.json). It subscribes to `rtl_433/events`, keeps the one sensor you name (`model` and `id`, so a neighbour's sensor is ignored), maps the fields and sends once a minute:

| rtl_433 | NuaSense node |
|---|---|
| `temperature_C` | `temperature` |
| `humidity` | `humidity` |
| `pressure_hPa` | `pressure` |
| `wind_avg_m_s` (or `wind_avg_km_h` ÷ 3.6) | `wind_speed` |
| `wind_max_m_s` | `wind_gusts` |
| `wind_dir_deg` | `wind_direction` |
| `rain_mm` | `rain_total_mm` |
| `light_lux` | `light_lux` |
| `uv` / `uvi` | `uv` |

Put the station token from the NuaSense console (External stations → Add a station → the part after `/station/`) into the station node. The first upload shows in the console within a minute.

**Home Assistant:** the rtl_433 MQTT auto-discovery gives you the sensor entities; forward them in Wunderground format with a `rest_command` on a `time_pattern` of one minute, or hand them to Node-RED as above. The NuaSense integration for Home Assistant reads the results back as sensors.

## Notes

- Keep one reading per minute; the receiver stores at most one per station per minute.
- Pressure: most sensor arrays have none; the receiver copes, and the forecast still works from the position.
- The station's path is bound to the first sender that uses it (the Node-RED node's device id). Keep that stable.

## Your data

When you connect a station, NuaSense stores its readings and computes your forecast, spray windows and risks from them. The readings are used aggregated and anonymised to improve forecasts and models for everyone; they are never passed on individually without your opt-in. You can disconnect the station in the console at any time and have all its data deleted.
